# agrouter

Go CLI that asks a routing classifier (TypeSafe's Jev by default) which `(cli, model, effort)` should run a prompt, then prints the decision or runs the chosen CLI. Module `github.com/svtlv/agrouter`, Go 1.27, dependencies vendored.

## Layout

```
cmd/agrouter/          # go-flags parsing, app pipeline (app.go), debug output, exit codes; end-to-end tests
pkg/config/            # INI loading, layering (embedded < global < local < env), validation
pkg/config/defaults/   # embedded config: the v1 catalog and invocation descriptors (the only place catalog names live in production)
pkg/catalog/           # options (model x effort), option ids, model/alias lookup
pkg/args/              # request model, argv building from invocation descriptors, native model/effort detection from the descriptors' templates (`native.go`), redaction
pkg/prompt/            # prompt sources (-p, positional, --prompt-file, stdin), --doc, strict file reads, mentioned files, request budget (policy: `request_tokens`, `bytes_per_token`), chunking, doc splitting
pkg/classifier/        # hand-written HTTP client for the routing classifier (url from the selected `[classifier.<provider>]`): neutral types, shared validation, retry, deadline and redaction, plus one wire codec per provider (`typesafe.go`, `openai.go` behind the `wire` interface in `wire.go`) that encodes the request, decodes the answers and normalizes error codes; the provider's limits (`Limits`), TypeSafe's long-context header, overflow classification and reported input tokens
pkg/router/            # eligibility, complexity stage (--doc), staged routing (cli -> model -> effort), classifier questions, chunk fan-out and pooling, cannot-decide policy
pkg/runner/            # child process, stdin replay, Windows Job Objects, .cmd quoting; bounded prompt-free probes (own process group / Job Object, response limit)
pkg/readiness/         # exec-only availability: executable lookup, prompt-free probes (json-helper, SDK control usage, JSON-RPC rate limits), evidence evaluation against options
```

Dependencies point one way: `classifier` <- `config` <- `catalog` <- `router` (`config` imports `classifier` only for provider names and capabilities: `Providers()`, `SupportsLongContext`); `config`, `catalog`, `runner` <- `readiness` (which never imports `router` or `classifier`); `prompt` depends on nothing internal; `cmd/agrouter` wires everything.

## Rules

- **CLI, model, and effort names come only from config.** Production Go code outside `pkg/config/defaults` must not hardcode catalog names, model aliases, or effort levels, including in help text. Per-CLI behavior and invocation descriptors (`exec_args`, `model_args`, `effort_args`, `prompt_args`) belong in `[cli.*]`; models and efforts come from `[model.*]`/`[effort.*]`. `cmd/agrouter/guard_test.go` enforces this; tests, testdata, and mocks may use explicit synthetic names.
- **stdout carries only the decision JSON** (and `--help`/`--version`) or the child's output in exec mode. The decision JSON is printed also when the classifier cannot decide with more than one CLI left (exit 2 beside the stderr error line), with `null` values and reasons. Decision JSON and the exec selection line carry `reason` (typed-error code, stage, fixed message) on routing failure and `null_reasons` for every null field; codes come from typed errors (`classifier` sentinels, `router.StageError`) in `cmd/agrouter/reason.go`, never from messages or bodies. Exec logs one `agrouter: selection: {json}` line with `cli`, `model` and `effort` to stderr before starting the child, without the prompt or argv; the prefix keeps callers that merge stderr into a stream-json stdout (ralphex) from dropping it as an unknown event. Warnings, one-line `agrouter:` errors and `AGROUTER_DEBUG=1` output also go to stderr, with the prompt and API key redacted; debug output never includes `--doc` text. Every line agrouter itself writes to stderr is also appended, stamped, to `<log_dir>/agrouter.log` (`pkg/config` `log_dir`, default `.agrouter/logs`, always on) by the tee in `cmd/agrouter/consolelog.go`; the child's output and stdout are never mirrored, and a log failure never changes console output or the exit code. For the default directory agrouter keeps the log gitignored through `.agrouter/.gitignore`; a custom `log_dir` is user-managed. A readiness block prints `agrouter: routing skipped: ...` (before routing) or `agrouter: run skipped: ...` (after it) before its own line. The one exception to the `agrouter:` prefix is exec's quota block line, which starts with the blocking check's configured `error_prefix` (for example a severity prefix) so a caller can match it as a limit message.
- **Invocation:** `agrouter [options] [prompt]` decides; `agrouter exec [<cli>] [options] [prompt] [-- native args...]` runs. The exec operand is optional: the token right after `exec` is the CLI only when it names a configured CLI (a disabled one is exit 2, never the prompt), otherwise it is the positional prompt. `--cli` pins the CLI in exec too; a conflicting `--cli` or one naming a disabled CLI is exit 2. Decision mode rejects `--` and pins only through `--cli`. Native tokens after `--` reach the child unchanged (never stripped, rewritten or reordered) and are never read as a prompt, routing constraint or readiness context, except that each candidate CLI's own `model_args`/`effort_args` templates (`args.NativeSelection`) recognize a native model or effort: it fixes that field, can imply the CLI, is skipped by routing and is not generated again. Argv is `exec_args`, generated model/effort for the fields left unset, the whole native argv, then `prompt_args`; `--verbose` before `--` is agrouter's only, and the exec selection line is always concise. `-p`/`--prompt`/`--print` are one option. `--model`/`-m`/`--effort` are not agrouter options in either mode (hidden, exit 2 with a hint to use the CLI's flag after `--`). `AGROUTER_CLI` is ignored with a warning; there are no child-option flags (`--permission-mode`, `--output-format`, `--sandbox`, `-c`, ...).
- `--doc` is routing-only: never in the child's argv. Routing has no capture, chunk-count or parallelism limits; only `[agrouter] timeout` bounds it.
- **Routing request size is configured, never recovered.** The selected `[classifier.<provider>] request_tokens` (the whole request: state plus its questions) and `bytes_per_token` size every request through `prompt.Policy`/`prompt.Budget`; code owns no budget constants beyond `AnchorTokens`, `attachmentShare` and `MinStateTokens`. The provider's hard limits live only in the adapter (`classifier.Limits(provider, longContext)`); `router.New` checks the selected section's `request_tokens` against them less a 2000-token reserve. There is no re-split, halving or resend: a 400 `max_tokens_exceeded` is `classifier.ErrTooLong`, reason `request_too_long`, and the user tunes the config. User-facing names for new keys, reasons and messages stay provider-neutral; provider specifics stay in `pkg/classifier`.
- **The classifier is configured, never named in code.** `[agrouter] classifier_provider` (`typesafe` by default, or `openai`) selects one of two sections, `[classifier.typesafe]` and `[classifier.openai]`; each holds `url`, `api_key`, `model`, `request_tokens` and `bytes_per_token`, and `long_context` only where `classifier.SupportsLongContext` allows it (TypeSafe). After merging, `cfg.Classifier` is the selected section with `Provider` set, and only that section's required keys are validated. The old flat classifier section is an error with a migration hint. `[agrouter]` keeps `classifier_provider`, `timeout`, the two policies and `log_dir`. The key comes from `--api-key`, then `AGROUTER_CLASSIFIER_API_KEY`, then config, and `runner.childEnv` strips the env var from the child. Production Go code outside `pkg/config/defaults` must not contain "jev" in any case (`TestGuard_NoJevNamingInProduction`); provider specifics are worded as TypeSafe's or OpenAI's and live only in `pkg/classifier` (each codec maps the neutral `classifier.Request` to its wire body and normalizes its too-long error code to `max_tokens_exceeded`, so `ErrTooLong` and the reason codes stay provider-neutral). Old names get no aliases: removed keys are unknown keys.
- **Config holds only policy; code owns question structure.** `[agrouter] routing_policy` and `complexity_policy` carry the cost/quality preference; stage questions, state guides, relevance/evidence questions and the complexity rubric are constants in `pkg/router/question.go`. Routing is staged (`cli` -> `model` -> `effort`, `pkg/router/stage.go`): a stage with one candidate, including one fixed by `--cli`, the exec operand or a native model/effort, is skipped; any stage failure fails the whole routing.
- There are no per-CLI argument mappings or selection/context metadata lists, and no hardcoded native flag names: a native model/effort is recognized only through the CLI's own `[cli.*]` templates (exact tokens, the `--flag=value` form of a two-token long flag, literal text around the placeholder, optional quotes; last match wins; empty, dangling and lookalike values are no selection). Spellings no template lists (for example Codex's `-m`) pass through. Values resolve against that CLI's catalog; values outside it pass through and the child validates them. Without a pinned CLI, the CLIs that matched are the only candidates and exec probes every candidate in parallel. Placing generated templates before the native argv gives native selections precedence under the child's override semantics. Readiness probes and default metadata describe agrouter's configured context, independently of native settings/profile/provider overrides.
- Exit `2` only for the cases in the README's exit code table (usage errors including `--model`/`-m`/`--effort`, `--cli` conflicts, `--` in decision mode and a duplicate separator, bad `--prompt-file`/`--doc` files, config errors, no decision with more than one CLI left); `127` when the child can't start, or when exec's readiness preflight finds the executable missing, authentication failed or the subscription quota exhausted; a strict (`unknown = block`) unverified availability is exit 2; exec with a classifier failure and more than one CLI left is exit 2 and starts nothing. Readiness checks run only in exec, before any classifier request; decision mode never probes. Native options never disable readiness checks. Exec stops on a preflight block only when every candidate CLI is blocked.

## Code style

- Comments lowercase except godoc; errors wrapped with `%w` and context.
- Consumer-side interfaces (`Classifier` in `pkg/router`, `CommandRunner` and `ReadinessChecker` in `cmd/agrouter`) with moq mocks in `mocks/`, regenerated with `make generate` (`go tool moq`, pinned in `go.mod`; no separate install).
- US spelling (`summarize`, `recognized`): the `misspell` linter is set to US.

## Testing

- Table-driven tests with testify; coverage 80%+ per package, mocks excluded.
- Test behavior, not the current configuration contents. Do not pin the shipped model list, model versions, option counts, default values, invocation descriptors, or equality with a documentation config block. Use explicit synthetic fixtures for catalog, filtering, lookup, and request-format tests; keep a smoke test that embedded config loads and validates.
- Readiness probes are tested with synthetic jsonl fixtures in `pkg/readiness/testdata/{control,rpc}` replayed by a fake peer; no test starts a real CLI.
- Child processes: the test binary doubles as the fake CLI when `GO_WANT_HELPER_PROCESS=1` (`cmd/agrouter/app_test.go`, `pkg/runner/runner_test.go`, `pkg/readiness/readiness_test.go`); it records argv, stdin and env. The classifier is an `httptest` server or the moq mock.
- Golden requests in `pkg/router/testdata` use a synthetic catalog, independent of the embedded defaults: `go test ./pkg/router -update` rewrites them. Wire-body goldens in `pkg/classifier/testdata` pin each provider's POST body (`go test ./pkg/classifier -update`); TypeSafe's must stay byte-identical, so never regenerate it casually.
- Platform tests sit behind build tags (`runner_unix_test.go`, `runner_windows_test.go`) and only run on their own OS in CI.
- `.gitattributes` forces LF so fixtures and embedded defaults are byte-identical on Windows.
- `make eval-routing` runs `//go:build eval` tests against the real classifier API (needs `AGROUTER_CLASSIFIER_API_KEY`, the key for the selected `classifier_provider`; it reads the embedded, global and local config); never in CI.

## Commands

```sh
make test       # locally without -race (no cgo on the dev machine); CI runs make test RACE=-race
make lint       # golangci-lint v2.14.0 (CI pin); override with GOLANGCI_LINT=<path>
make build      # .bin/agrouter on master; .bin/agrouter.<branch> otherwise (with .exe for Windows builds)
make generate   # moq mocks
make fmt        # needs goimports: go install golang.org/x/tools/cmd/goimports@latest
```

Older golangci-lint builds, including v2.13.0, cannot decode the Go 1.27.2 stdlib export data (version 5) and fail typechecking; use v2.14.0 (`go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.14.0`). Rebuilding v2.13.0 with the local Go does not fix its export-data reader. Check lint for `GOOS=linux` and `GOOS=darwin` too, and with `--build-tags=eval`.
